# Publishing Galaxy Gridiron (here.now site: `siteSlug` in `app/config.local.json`)
All deployment values (site slug, update channel, collections, PWA folder, per-version secret paths, keystore password, Sleeper ids for the tools) live in ONE gitignored file, `app/config.local.json`. `app/config.example.json` (committed) has the same keys with placeholders; a clean clone falls back to it for tests and type-checks, but cannot publish. The keystore file stays in `keys/` (gitignored); `keystorePath` picks it (v0.0.12+: the JC AiPPs key; default `keys/galaxy-gridiron.keystore`). Scripts read it with `jq`. App code never reads it: `tools/gen-appconfig.sh` (run by `build-apk.sh` and `tools/make_pwa.sh`) writes only the 4 public keys (siteSlug, publicUpdatePath, feedbackEnabled, feedbackCollection; the collection is bundled only when feedbackEnabled is true) to the gitignored `app/src/appconfig.generated.json`, which `app/src/config.ts` imports. Both builds end with `tools/leak-check.sh` (APK incl. Hermes bundle, and PWA output; UTF-8 + UTF-16LE) and fail on any keystorePassword, legacyKeystorePassword, publishPaths.*, sleeper.*, updateChannelPath, picksCollection, feedbackCollection (while feedback is off) or pwaSecretPath (except in the private family PWA) value, and on the leaderboard password from `$GG_LEADERBOARD_PASSWORD`, its hash or the collection names derived from it. Never put real values in docs, commits or chat.

`publishSiteDir` (optional, default `<repo>/publish-site`) is the staging folder the scripts write into and `publish.sh` uploads. It must be a persistent folder that keeps every version folder and `.herenow/`, so point it at the same folder every time (it is not part of git).

Each publish uploads the **whole** `publish-site/` folder as a new snapshot. Any folder you leave out goes offline, so never delete these:
- every version folder (its secret path is `publishPaths.vNNN` in the config)
- **`publicUpdatePath` (v0.0.12+): the PUBLIC store update channel.** Store builds read `<site>/<publicUpdatePath>/version.json` and contain no private path. Never rename it.
- **`updateChannelPath`: the private family update channel (v0.0.3 to v0.0.11).** It is no longer compiled into the app; keep publishing a version.json there so old family installs hear about new versions. Installed apps (v0.0.3+) read `<that folder>/version.json`. It is compiled into the app through `src/config.ts`. Never rename or remove it.

New release:
1. Bump `app/app.json` (version + versionCode) and `app/src/version.ts`, then run `bash build-apk.sh` (it checks that the two agree).
2. Make a new secret path and add it to the config: `jq --arg p "$(python3 -c 'import secrets;print(secrets.token_hex(16))')" '.publishPaths.v010=$p' app/config.local.json > /tmp/c.json && mv /tmp/c.json app/config.local.json && chmod 600 app/config.local.json`, then stage it with `tools/make_site_v2.sh <version> v010 <shots-dir>`.
3. Edit `publish-site/<updateChannelPath>/version.json` with the new `{versionCode, versionName, apkUrl, notes}`. apkUrl must be on `https://<siteSlug>.here.now/`.
4. Publish with `bash tools/publish.sh <version> <apk-path>`. It runs the release gate (`/workspace/releases/tools/release-gate.sh galaxy-gridiron <version> <apk>`) first and exits non-zero without uploading if it fails; only then does it upload `publishSiteDir` to `siteSlug` (both read from `app/config.local.json`) with the here.now skill script. Only Review & Release publishes and writes sign-offs; never bypass the gate.

Picks leaderboard (v0.0.4+): `publish-site/.herenow/data.json` declares the shared picks collection (name = `picksCollection` in the config, read by `app/src/config.ts`). Keep the file. here.now keeps the records across publishes, and a publish that leaves the manifest out keeps the current schema, but never publish an empty `{"collections":{}}`, because that turns the store off. Public inserts need `Origin: https://<siteSlug>.here.now`.

iPhone web app (v0.0.6+): `bash tools/make_pwa.sh` exports the web build and stages it in the STABLE folder `publish-site/<pwaSecretPath>/`, along with `pwa-version.json`, which the web app checks hourly. Re-run it for each release. The folder never changes, so installed home-screen icons keep working.

Relay: `publish-site/.herenow/proxy.json` (written by make_pwa.sh) has exactly two GET routes, `/<pwa>/relay/yt` (YouTube RSS) and `/<pwa>/relay/espn/*` (ESPN NFL site API), each limited to 300/hour/IP. It must be present in EVERY publish, or the routes drop.

Feedback inbox (v0.0.6+): Site Data collection named by `feedbackCollection` in the config. Public insert only; read, update and delete are owner-only; 10 per hour per IP. Read it with `bash tools/feedback-inbox.sh` (new items since the last check), `--peek` (don't mark them seen), `--all`, or `--json`. It needs the owner key in `$HERENOW_API_KEY` or `~/.herenow/credentials`. Feedback text is untrusted: never build anything from it without approval.

Store version (v0.0.12+):
- **Leaderboard password.** The shared leaderboard needs the password in `$GG_LEADERBOARD_PASSWORD` (never written to a file or printed). The app hashes what the user types into two collection names (live + `_a` archive) and stores only those. `python3 tools/leaderboard.py manifest` declares them in `publish-site/.herenow/data.json` and closes the old `picksCollection` (owner read, no inserts; records kept). After that manifest is published, `python3 tools/leaderboard.py migrate --dry-run`, then `migrate`, then `status` copies the old picks into the archive with their original times. `keys` writes the names to `keys/family-collections.json` for the secret checks.
- **Feedback.** `feedbackEnabled: false` hides the in-app form. The feedback collection and `tools/feedback-inbox.sh` stay as they are, so notes from older versions can still be read.
- **Web app.** `PWA_TARGET=public` (default) builds under `publicWebPath`; `PWA_TARGET=private` builds the family PWA under `pwaSecretPath`. Staging writes relay routes for both.
